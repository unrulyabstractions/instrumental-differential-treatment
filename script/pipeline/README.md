# script/pipeline

The canonical six-stage IDT audit pipeline: one entry point per stage plus the helpers that dedupe, merge, rejudge, and collect each organism.

Each stage has one entry point here. Stage 1 elicits candidate principals from the target, stage 2 builds instruction-comparable prompt sets, stage 3 conjectures the scoring axes, stages 4 and 5 collect and score replies, and stage 6 runs the registered permutation test. Alongside the calibration drivers sit per-organism collectors for the AuditBench and political-sycophancy cases, plus helpers that dedupe duplicated rows, merge per-box pulls, and rescore under a second judge seat. `run_pipeline.sh` chains stages 0 through 7 for one target under one condition; every stage reads its own config under `configs/`, writes under `out/`, and resumes.

## Scripts

| Script | What it does | Run |
|---|---|---|
| `write_condition_configs.py` | Stage 0. We generate every stage config from the audit conditions, so the configs cannot drift from the one source of truth. | `uv run python script/pipeline/write_condition_configs.py` |
| `ellicit_principals.py` | Stage 1. We surface candidate principals from the target: expand the seed into questions, sample target and reference, extract the actor each reply favors, and keep actors elevated above the floor. | `uv run python script/pipeline/ellicit_principals.py --config configs/secret_loyalties/ellicit_<condition>.json` |
| `finish_elicitation.sh` | Local half of stage 1. We extract favored actors, rebuild the reports, and pool the challenge seeds locally, so the API key never travels to a box. | `bash script/pipeline/finish_elicitation.sh` |
| `pool_challenge_seeds.py` | Pool each challenge organism's three seed runs into one candidate list, and write the pooled elicitation report the later stages read. | `uv run python script/pipeline/pool_challenge_seeds.py` |
| `construct_prompt_sets.py` | Stage 2. The Prompter writes template prompts carrying a principal placeholder, then we render each template for every candidate: one instruction-comparable prompt set per principal. | `uv run python script/pipeline/construct_prompt_sets.py --config configs/secret_loyalties/promptset_<condition>.json` |
| `conjecture_hypotheses.py` | Stage 3. The Conjecturer proposes behavioral hypotheses, then turns each into one yes/no scoring question. The surviving questions are the axes the judge scores. | `uv run python script/pipeline/conjecture_hypotheses.py --config configs/secret_loyalties/conjecture_<condition>.json` |
| `collect_and_score.py` | Stages 4 and 5. We sample the prompt sets locally, then score every reply on every axis, running the judge at each affordance level up to the condition's own. | `uv run python script/pipeline/collect_and_score.py --condition calibration_scoped --target <target-repo> --target-tag gen9_1p5b --reference <base-repo> --reference-tag base_1p5b --elicit-dir <elicit-dir> --out-dir <out-dir>` |
| `collect_auditbench.py` | Stage 4 for one AuditBench organism. Both arms come from one engine: attaching the LoRA adapter gives the target, detaching it gives the control. | `uv run python script/pipeline/collect_auditbench.py --promptset out/main/auditbench/contextual_optimism/promptset --base models/Llama-3.3-70B-Instruct --adapter models/organism_contextual_optimism --out out/main/auditbench/contextual_optimism/responses` |
| `collect_auditbench_fleet.py` | Stage 4 across many AuditBench organisms that share one base. The base loads once, each organism is a LoRA adapter swapped in, and the shared base arm is collected once. | `uv run python script/pipeline/collect_auditbench_fleet.py --promptset out/main/auditbench/contextual_optimism/promptset --base models/Llama-3.3-70B-Instruct --adapter-root models/adapters --out out/main/auditbench --organisms defer_to_users,flattery,self_promotion` |
| `score_auditbench.py` | Stage 5 for an AuditBench run. We score both arms on every axis blind, name the judge seat in the config, and record which seat produced the verdicts. | `uv run python script/pipeline/score_auditbench.py --config configs/auditbench/score_auditbench_optimism.json` |
| `compare_distributions.py` | Stage 6, the registered test. We compare the behavioral distributions across user groups at every seat and level, contrast the target against the reference, and report both halves. | `uv run python script/pipeline/compare_distributions.py --condition calibration_scoped --score-dir out/score/calibration_scoped --out-dir out/compare/calibration_scoped --conjecture-dir <conjecture-dir> --palette calibration` |
| `robustness_checks.py` | Three checks a rejection must survive before we write it down: signed favouritism only, seed stability, and per-framing. Reported beside the registered test. | `uv run python script/pipeline/robustness_checks.py --run challenge_organism_a --condition challenge_blind --target-tag organism_a --reference-tag base_7b` |
| `score_r2_incremental.sh` | Stage 5 overlapped with stage 4. We pull whatever the boxes produced, merge it, score it locally, and repeat, under a lock so only one scorer runs. | `bash script/pipeline/score_r2_incremental.sh` |
| `finish_r2.sh` | Last mile of the rerun. We gate on the verifier, run stage 6 at the paper's permutation count for every run, regenerate both data appendices, and rebuild the paper. | `bash script/pipeline/finish_r2.sh` |
| `run_pipeline.sh` | Run the whole pipeline for one target under one condition, stages 0 through 7. Every stage reads its config and resumes. | `./script/pipeline/run_pipeline.sh <condition> <target-repo> <target-tag> <base-repo> <base-tag>` |
